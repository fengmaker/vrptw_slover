# M4/M5 验收与性能记录

## 运行定义

在 `vrptw_solver` 目录执行：

```powershell
python -m vrptw batch data --seeds 0 1 2 --time-limit 0.5 --out runs/m5_delivery_seed012_0p5s
python -m pytest -q -p no:cacheprovider --basetemp=tests/.pytest-local
```

批量仅读取 `data/*.txt` 顶层原始 Solomon 文件。每例每种子给求解器 0.5 秒总预算，减车上限为每目标车数 100 次试探，ILS 每个候选最多接受 2 次局部移动。报告绘图时间不计入求解器预算，所有实际求解耗时仍逐例记录。结果数值规则是 `solomon_exact_1000_v1`；只在参考车辆数相同时计算距离差。

运行环境：Python 3.12.4、Windows 11（10.0.22621）、AMD64 Family 25 Model 68、16 个逻辑 CPU，求解器使用 1 个线程。批量开始于 2026-09-28 11:36:47 UTC，结束于 11:38:54 UTC。求解器源码 SHA-256：`e638d2769e94a4be304e946219ac90e761cb6f0b6c8c772ac267cad45c4c0855`；每个输入的 SHA-256 见汇总 CSV。

## 热点与后续判断

用 `cProfile` 分别分析 C101、R101、RC101，配置为固定种子 0、1 次 ILS 迭代、每目标车数 10 次试探、每候选最多 1 次局部移动：

| 实例 | `evaluate_route` 调用次数 | 主要耗时阶段 |
| --- | ---: | --- |
| C101 | 43,531 | 局部搜索移动评估，其次减车插入 |
| R101 | 43,476 | 减车插入 |
| RC101 | 82,856 | 减车插入 |

热点是大量候选位置反复完整计算受影响路线。当前 Python 版在全部 56 个实例上保持可行且能在短预算下完成批量运行，因此本阶段没有加入 C++。若要提高距离与车辆质量，先尝试缓存已评估路线、筛选空间/时间邻居和更有效的修复顺序；每项加速都须继续与完整重算核对。对未找到更少车辆的实例，只能报告预算内未找到，不能断言较小车队不可行。
