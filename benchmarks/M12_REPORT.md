# M12 原生热点迁移验收

M12 将可行固定车数搜索的候选枚举、邻居筛选、七种移动应用和路线时间前缀／后缀合并作为一个整体移入 C++17／pybind11。两轮 56 实例 × 三种子 × 0.5 秒串行交替对照，原生后端均为 **55 例同车数距离改善、0 例退步、1 例打平，最好解车辆数不变**。同车数固定上限 PyVRP gap 中位数分别为 **9.2651%／8.8562%**，Python 控制均为 **23.1035%**。通过默认晋级，`solve`／CLI 默认 `search_backend="auto"`；扩展缺失或配置不兼容时使用 Python。M11 不可行搜索继续默认关闭。

当前 **348 项测试通过**。原生扩展已在 Windows x64、CPython 3.12.4、pybind11 3.0.1、setuptools 75.6.0、MSVC 195035722 的 C++17／`/O2` 配置下构建成功。[构建记录](m12/build_receipt.json)保存依赖、源码和二进制哈希。数值合同仍为 `solomon_exact_1000_v1`，正常求解无 PyVRP 依赖，未直接复制其实质性源码。

## 热点与迁移边界

[剖析](m12/profile/profile.json)先在原 Python 后端的 C103／C104／R101／RC101 上运行。移动 `delta` 占局部搜索累计时间约 85%～87%；路线增量评估是其中主要部分。C103／C104 局部搜索阶段约 0.263／0.268 秒，R101／RC101 则只有 0.069／0.062 秒，后两类还有约 0.238／0.236 秒用于修复。cProfile 和诊断会改变计时，这组结果只用于确定迁移范围。

原生代码直接读取 Python 已生成的整数矩阵，不使用 C++ 浮点重新计算弧。扫描次序、first／best、固定／轮换调度、完整邻域和 top-k 过滤保持原含义；同值移动仍按原枚举顺序裁决。缓存仅在接受移动后更新，受影响源路线或结果路线为空时拒绝移动。扫描超时丢弃部分 best，保留已经接受且独立验证过的完整解。

Python 继续处理输入、构造、减车、扰动修复、ILS 接受控制、报告和最终验证。每个原生接受移动都调用原 `validate_solution`，同时核对可行性、固定非空车辆数及整数距离差。原生后端不处理 M11 软罚分搜索，也不支持 `full`／`cached` 评估；`auto` 对这些配置使用 Python，显式 `native` 报错。低层 `improve` 默认仍是 Python，供独立调用和对照使用。

安全 int64 域为至多 100000 位客户、每个距离／需求／容量／时间标量不超过 `10^12`；构造器检查矩阵维度、客户覆盖、源路线可行性和索引，提前拒绝越界与整数溢出输入。`auto` 对超出该域的公开 Instance 回退 Python，不改变 Python 任意精度整数合同。扩展采用模块局部类型绑定，允许公开验证器与多个冻结实验包在同一进程共存。

## 正确性与固定工作量

新增测试将 **2310 个真实随机移动**逐一与完整 Python 重算对照，覆盖 C103／R101／RC101 的七算子；另覆盖等待、精确时间窗、容量／回仓边界、更新后的移动序列、空路线槽、非法矩阵／客户／极端索引及整数域回退。七算子正序／反序、first／best 和 fixed／cyclic 的完整接受轨迹与 Python 一致，稀疏邻居扫描也一致。

[固定工作量](m12/fixed_work/fixed_work.json)从确定性构造路线开始，各后端接受 30 次移动，交替运行三次；分别关闭／开启诊断。全部路线、接受移动、整数距离、候选数及拒绝分类一致，共 48 条最终路线另行独立验证。下表使用**关闭诊断**的耗时中位数，计入原生初始化、缓存应用以及每次 Python 完整验证，不把诊断批量计数带来的优势当作普通吞吐收益。

| 实例 | 相同候选数 | Python 秒 | 原生秒 | 提速 |
| --- | ---: | ---: | ---: | ---: |
| C103 | 14307 | 0.145177 | 0.012635 | 11.49× |

[代表诊断](m12/diagnostics/metrics.json)共 24 条路线全部可行。12 次原生运行相对各自 Python 控制均改善距离、车辆数相同。Python 局部搜索累计 2.929271 秒、231717 个候选、350 次接受；原生累计 2.614981 秒、4026013 个候选、1196 次接受。候选量约增至 17.37 倍，但搜索路径不同，这组数据不是严格固定工作量吞吐。诊断只解释行为，默认晋级使用以下全量非诊断结果。

改善／退步使用每实例三个种子的车辆优先最好目标。逐次对照另保留：首轮为 **160 改善、2 退步、6 打平**，复验为 **164 改善、0 退步、4 打平**。首轮两次退步如下，没有按三种子汇总删去：

- R205／种子 2：Python 3 车，原生 4 车。双方从同一 4 车构造解开始，首次可行时间为 0.264556／0.292414 秒；目标 3 车均尝试到第七轮，Python 在截止前修复完成，原生在该轮超时。距离不跨车辆数比较。

## PyVRP 参考与最终交付

复用 M10 已归档的固定车辆上限、同输入、同三种子和 0.5 秒 PyVRP 记录；本轮未出现需要补跑的新最好车辆上限。所有可行参考路线再次由本项目验证。该参考是距离协议，未在本轮重跑显式 `minimise_fleet`，M10 的独立减车协议与本表分开。

| 批次／后端 | 同车数实例 | 自研车数更多 | gap 中位数 | 最近秩 90 分位 |
| --- | ---: | ---: | ---: | ---: |
| 首轮 Python | 53 | 3 | 23.1035% | 63.9723% |
| 首轮原生 | 53 | 3 | 9.2651% | 42.8325% |
| 复验 Python | 53 | 3 | 23.1035% | 64.2127% |
| 复验原生 | 53 | 3 | 8.8562% | 42.8326% |
| 最终默认 CLI | 53 | 3 | 8.9252% | 42.8325% |

最终默认 CLI **168/168 可行**，完成 543 轮 ILS；实际求解墙钟中位数／最大为 **0.500590／0.501205 秒**，首次可行中位数／最大为 **0.112776／0.367164 秒**。最终 C／R／RC 的同车数 gap 中位数分别为 **4.8569%／11.7519%／12.8936%**。与复验原生跨批比较车辆数不变，距离改善／退步／打平为 **17／7／32**，截止边界仍有波动，最终实测不能用某轮最好值替代。

完整分组及输出哈希见 [verification.json](m12/verification.json) 的 `comparisons.delivery` 和 `delivery_artifact_sha256`。交付保留每次 JSON、SOL、轨迹 CSV，原始 `runs/m12_delivery/` 另外保留全部路线图与收敛图；归档保留 C103／RC108、种子 0 的图，已抽查图像布局。53 个同车数实例的中位数已在两轮及最终交付低于 10%，但仍有 3 例车辆差距和约 42.83% 的长尾 90 分位，不能解释为全面接近最优。

## 复现与证据

源码、输入、配置、原生二进制、运行顺序和各结果文件全部有 SHA256。实验源码包与二进制指纹为 `a5385b24e1b1e895647141e361fbfd125f69b22b8101a03a5bf03d0a059bf87a`；最终交付只将 `Config`／CLI 默认改为自动选择，最终源码指纹为 `ffd80526f613022a3ba48d295a353e9a1f516759a5474a53675463ce25283847`。二进制指纹为 `604462f386c003e397cd55934c67735731d9683e762902ff4d23fad1f410c0bb`。构建可按命令复现，不承诺 MSVC 重新链接后的字节级哈希相同；实验保留本轮确切二进制。`.pyd` 为本地生成产物，不纳入 Git。

实验分析拒绝源码／二进制／输入／结果／预算／配置篡改及未完成批次；即使更新结果哈希，虚报车辆数也会被独立验证拒绝。全量两轮共 672 条、代表诊断 24 条、固定工作量 48 条、最终 CLI 168 条，合计 **912 条自研完整解**独立重验；另有 **208 条已有 PyVRP 可行参考解**。完整归档文件哈希见 [archive_manifest.json](m12/archive_manifest.json)。
